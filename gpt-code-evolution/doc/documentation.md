# Documentation

- **Format.** `- **Short title.** Details.` One point per item; minimum necessary text.
- **Content.** Project-specific intent, decisions, trade-offs, and constraints—not obvious advice or code paraphrases.
- **Maps.** Show boundaries and relationships; link implementation details.
- **Ownership.** Features own behavior/change declarations; task indexes own order; task files own evidence; doc/ owns shared decisions. Link, never copy.
- **Skills.** `.pi/skills/<name>/SKILL.md` owns discovery metadata and references canonical docs, not duplicate rules.
- **Indexes.** Keep READMEs only for setup or navigation; remove obsolete redirects.
- **Accuracy.** Separate proposals from implemented behavior. Preserve task evidence and acceptance criteria.
- **Terms.** Use the [glossary](glossary.md).
